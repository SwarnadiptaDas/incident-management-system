Mission Objective: Build a resilient, production-ready Incident Management System (IMS) designed to monitor a complex distributed stack and manage failure mediation workflows.

1. Technical Architecture

The system is built on a distributed architecture using a Async Worker Model to handle high-throughput signal ingestion (10,000+ signals/sec).

  [ High-Volume Signals ] 
            |
            v
    +-------------------+
    |   FastAPI Ingest  | ----> [ Redis Buffer Queue ]
    +-------------------+               |
                                        v
                                +------------------+
                                |  Async Workers   |
                                +------------------+
                                 /       |        \
          (State Pattern)       /        |         \   (Strategy Pattern)
         [ PostgreSQL ] <------+   [ MongoDB ]      +----> [ Alerting ]
       (Work Items/RCA)          (Raw Signals)          (P0/P1/P2)

2. Key SRE Features BONUS Points

  • Atomic Debouncing: Implemented using Redis TTL windows (10s) to collapse 100+ identical signals into a single actionable Work Item.
  • Backpressure Handling: Decoupled ingestion API from processing using a Redis List as a high-speed buffer.
  • Database Separation:
    • PostgreSQL: Transactional Source of Truth for incidents and RCAs.
    • MongoDB: Schema-less Data Lake for long-term raw signal audit logs.
    • Redis: In-memory buffer and real-time aggregation engine.
  • Design Patterns:
    • State Pattern: Strictly manages incident lifecycles (OPEN -> INVESTIGATING -> RESOLVED -> CLOSED).
    • Strategy Pattern: Dynamically routes alerts (P0, P1, P2) through interchangeable notification logic.

3. Security & Observability

  • Rate Limiting: Redis-backed sliding window rate limiting at the API layer.
  • Deep Health Monitoring: Custom /health endpoint monitors status for Postgres, Mongo, and Redis.
  • Minutely Aggregation: Real-time timeseries tracking of signal frequency per component.

4. How to Run

The entire stack is containerized using Docker Compose:

docker compose up --build
